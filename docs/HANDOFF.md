## 3. 하드웨어 전체 그림

좌표는 mm이고 X는 왼쪽→오른쪽, Y는 앞→뒤, Z는 위입니다. 원점은 두 스테이션 사이, 바닥판 윗면입니다.

| 덩어리 | 위치 | 크기 |
|---|---|---|
| 가루 스테이션 P | 컵 중심 `cupP = [-110, 0]` | 판 210×210 |
| 알약 스테이션 L | 컵 중심 `cupL = [105, 0]` | 판 205×205 |
| 제어판 | `ctrl_c = [105, 152.5]` (L 뒤, 탁자 위) | 190×90 |

공통 높이:

| 항목 | 값 |
|---|---|
| 바닥판 두께 | `base_t = 6` (z −6~0) |
| 기둥 | 14×14, z 0~120 |
| 상판 | 아랫면 `deck_z = 120`, 두께 `deck_t = 5` → 윗면 `deck_top = 125` |
| 상판 테두리 | 아래로 `rim_h = 6`, 폭 `rim_w = 3` |

두 스테이션과 제어판은 따로 서 있고 전선으로만 이어집니다. 컵은 두 스테이션 모두 **4.5mm 들어 올린 뒤 앞(−Y)으로** 빼며, 그 길은 겹침 검사(`sweepP`, `sweepL`)로 확인합니다. 가루 쪽은 앞에 기둥이 없고, 상판 앞 테두리에 컵 폭+12 홈이 있습니다.

### 3.1 가루 모듈 (`powder.scad`) × 4

- **배치:** 가루 컵 중심에서 X자로 놓입니다 (`powder_a = [45,135,225,315]`). 출구 끝면이 컵 중심에서 `powder_d = 13`에 있습니다. 로컬 +Y가 바깥쪽입니다.
- **네 모듈의 경계:** 각 모듈은 자기 90° 구역 안에만 있도록 `own_sector()`로 잘려 있고, 이웃 모듈과 1.2mm 틈이 있습니다. 원래 앞 날개 모서리가 2.8mm 겹쳐서 이렇게 고쳤습니다.
- **관과 스크류:**
  - 관 안지름 16. 스크류는 지름 15, 피치 40, 날개 두께 3, 1줄 나선이고 코어는 6입니다.
  - 관 길이 `L = 85`, 축 높이 `axis_h = 24` (상판 윗면 기준).
  - 출구 13×12는 컵 쪽 끝 아래에 있습니다.
- **스크류 끝 핀:** `tip_d = 5`, 막힌 구멍 깊이 `tip_hole_d = 2.5`. 막힌 구멍이라 앞으로 가루가 새지 않습니다.
  - ⚠ 이 변수는 원래 이름이 `pin_*`였는데, config의 위치 맞춤 핀과 이름이 겹쳐서 `tip_*`로 바꿨습니다. 13장을 보세요.
- **부품 5개:**
  - `block`: 아래 반쪽 관 + 모터 받침
  - `top`: 위 반쪽 관 + 칼라 Ø33 + 호퍼 턱
  - `strap`: 모터 덮개 띠
  - `hopper`: 칼라에 씌우는 60° 깔때기, 윗구멍 `hop_top_id = 70★`, 테두리 Ø80
  - `auger`: 스크류
- **모터 고정 (JGA25-370):**
  - 받침 윗면을 축보다 1mm 낮췄습니다 (`split_dz = 1.0`).
  - 띠 구멍 중심을 축보다 0.4 낮췄습니다 (`squeeze = 0.4`). 그래서 M3x12 두 개로 조이면 감속기를 약 0.3mm 눌러 잡습니다.
  - 겹침 검사에서 `motor×powder` 76mm³는 이 조임이라 허용합니다 (`ALLOW` 250mm³).
- **스크류 허브:** D컷 구멍 `hub_hole = shaft_len − boss_h − 0.5 + 1.5`. 모터 돌기(boss)에 닿지 않게 `auger_y_end = L − boss_h − 0.5`로 끝냅니다.
- **나사 없이 조립:**
  - 상판 ↔ block: 앞 날개 핀 2개 (`powder_deck_holes()`, ±25)
  - block ↔ top: 대각선 핀 2개 (`pin_at`)
  - 위에 호퍼와 가루통이 얹혀서 무게로 눌립니다.
- **상판 전선 구멍:** 모터 전선은 대각선 r=128, Ø9 구멍으로 내려갑니다 (모터 몸통 바로 아래).
- **가루통:** 다이소 용기, 바닥 한 변 85 이하 ★. 바닥에 Ø70 구멍을 뚫어 호퍼 테두리 위에 얹습니다.

### 3.2 알약 모듈 (`pill.scad`) × 4

- **배치:** 알약 컵 중심에서 2×2로 놓입니다 (`pill_s = 51`, 모듈 중심이 대각선 72.1). 로컬 +Y(출구 90°)가 컵 쪽입니다.
- **원판:** 칸 3개, 칸 중심 반지름 `pocket_r = 27`. 원판 지름 71.8, 모듈 지름 80.0.
- **칸 크기:**
  - 캡슐 00호 23.5×8.5×8.5 ★ 기준
  - 칸은 캡슐보다 길이 +1.8, 폭 +1.0 크고, 원판 두께는 캡슐 두께 +0.8
  - 칸 윗면을 1mm 모따기했습니다.
- **대기 위치:** 칸이 30°·150°·270°에 있고 출구는 90°입니다. 칸 끝이 출구에서 6° 이상 떨어져 있습니다 (`rest` 검사).
  - 한 알 = 120° 회전입니다.
  - 원래 칸이 4개였는데, 4개면 어떤 각도에 세워도 칸이 출구에 걸쳐서 3개로 바꿨습니다.
- **덮개 창:** 출구 ±75°는 닫혀 있고, 나머지 구간으로 호퍼 속 알약이 칸에 들어갑니다. 창이 끝나는 쪽 모서리는 아래를 45°로 깎아서, 반쯤 걸친 알약을 끼우지 않고 밀어 넣습니다.
- **틈:** 원판 아래 0.5, 위 1.5.
- **축 구멍:** 28BYJ 축은 끝의 6mm★(`byj_flat_len`)만 D컷이라, 원판 구멍도 아래는 둥글게, 위쪽만 D자로 만들었습니다.
- **부품과 출력 방향:**
  - `skirt`: 모터가 들어가는 치마 + 낙하관 + 상판 핀 날개 2개 (30°, 210°) + 윗면 턱
  - `floor`: 바닥 + 원판 우물 + 덮개 턱
  - `disk`: 원판. 뒤집어서 출력
  - `cover`: 덮개 + 호퍼 70mm★
- **치마 ↔ 바닥:** 나사 없이 치마 윗면 안쪽 턱(1.2×2)에 바닥 아랫면 홈이 끼워집니다. 150°에 돌림 방지 키가 있습니다.
- **모터 (28BYJ-48):**
  - 귀 두 개를 아래에서 M3x5로 바닥에 조입니다.
  - 너트는 바닥 윗면(우물 쪽) 주머니에 들어가고, 주머니는 0.8 더 깊게 팠습니다.
  - ⚠ **M3x5보다 긴 나사를 쓰면 끝이 원판 밑에 닿습니다.**
- **원점 (홀 센서):**
  - 원판 아랫면 칸 사이에 자석 8×3 (r27.5, 대기 상태에서 350°)
  - 바로 아래 바닥 밑에 홈을 파서 바닥을 1.2mm만 남기고, 49E 센서 알맹이를 넣습니다.
  - 센서 다리와 단선은 바깥쪽 홈(7×1.8)을 따라 치마 벽으로 갑니다.
  - 자석과 센서 사이는 약 1.7mm입니다.
  - 센서는 KY-035 보드에서 떼어 다리에 단선을 납땜하고 수축튜브를 씌웁니다.
  - 센서를 홈에 고정하는 방법은 정하지 않았습니다. 테이프나 글루건 정도면 됩니다 ★.
- **전선 창:** 치마 −Y쪽에 24×14. 상판 전선 구멍(20×12)은 모듈 로컬 (0, −30)에 있습니다. 28BYJ 커넥터(약 12.5×6★)가 꽂힌 채로 통과합니다.
- **미끄럼관:** 출구에서 컵까지 이어지고, **알약 상판과 한 덩어리**로 출력합니다 (`pill_slide_solid/hole`).
  - 위: r = 45.1, z = 120
  - 아래: r = 22, z = 87 (컵을 들어 빼도 닿지 않는 높이)

### 3.3 저울 (`scale.scad`)

- **로드셀:** 1kg 바 타입 (80×12.7×12.7, 치수도). X 방향으로 가루 컵 아래에 눕힙니다.
- **고정 끝 (전선 나오는 쪽):** M5x15 두 개를 받침 아래에서 올려 끼웁니다. 머리는 5.2 파묻히고, 나사가 로드셀에 8.2mm 물립니다.
- **쟁반 끝:** M4x12 두 개를 쟁반 위에서 내려 끼우고, 사이에 간격 와셔 3mm를 넣습니다. 쟁반 두께는 7, 머리는 4.2 파묻히고, 6.2mm 물립니다.
- **assert:** 물림 길이가 5 이상이고 로드셀 두께보다 짧은지 파일 안에서 확인합니다.
- **받침:** 멈춤대까지 한 덩어리 띠(두께 6)입니다. 로드셀 끝 아래에 1.0mm 틈을 둔 과부하 멈춤대가 있습니다. 바닥판에는 핀 2개로 놓습니다.
- **컵 높이:** 컵 바닥은 z 34.7, 컵 윗면은 109.7 ★(컵 높이 75 기준).

### 3.4 뼈대 (`frame.scad`)

- **기둥:**
  - P 7개 `postsP` (컵 기준 ±93, 앞쪽 없음), L 7개 `postsL` (±92)
  - 양 끝에 6×6×4 네모 돌기가 있고, 판의 네모 관통 구멍에 끼웁니다.
  - 돌기는 기둥 한쪽 면에 붙어 있습니다 (`peg_off = -4`). 눕혀서 출력할 때 바닥에 닿게 하려는 것입니다.
  - L 기둥은 원래 ±93~95였는데 상판 테두리를 파고들어서 ±92로 옮겼습니다.
- **상판:** 뒤집어서 출력합니다. 모듈 핀 구멍은 윗면에서 3mm 막힌 구멍입니다.
- **바닥판:** 보드 받침이 붙어 있고, 케이블 타이 구멍과 바닥판 아랫면 타이 홈이 있습니다. 알약 바닥판에는 알약 컵 받침 링(높이 4)이 있습니다.
- **핀:** `pins` 한 판에 30개 (필요 26 + 여분 4). Ø4×6.5, 구멍은 `pin_hole = 4 + 2*clear`.

### 3.5 전자부품 받침 (`electronics.scad`)

- **제어판 (190×90×3, 한 판으로 출력):**
  - 만능기판 89×52 홈 받침: −X에서 밀어 넣고 +X 끝에서 멈춥니다. 긴 변 2mm 턱이 기판 윗면을 덮으니, 그 2mm 안에는 부품을 두면 안 됩니다.
  - ESP32 받침: 세로로 놓고 짧은 두 끝만 받칩니다 (높이 30). USB는 뒤쪽(+Y)입니다. **점퍼를 먼저 다 꽂고 올려놓는 방식**입니다.
  - DC 잭 받침: 케이블 타이로 고정합니다.
- **바닥판에 붙은 보드 받침** (가장자리 턱 1.5, 보드 아랫면 높이 4, 짧은 두 변은 열림, 케이블 타이 하나):
  - ULN2003 ×4: 알약 컵 기준 (±62, ±62). 각 알약 모듈 전선 구멍 바로 아래입니다.
  - MCP23017: (0, 62)
  - HX711: 가루 컵 기준 (−55, 55)

## 4. 전자 · 배선 요약 (자세한 건 `hardware/wiring.md`)

- **전원:** 5V 4A 어댑터 하나. 코드에서 **한 번에 모터 하나만** 돌립니다 (최악 약 1.9A).
- **ESP32 핀:**

| 용도 | 핀 |
|---|---|
| I2C (MCP23017) | 21 SDA / 22 SCL |
| HX711 | 18 DT / 33 SCK |
| DRV8833 #1 | 25, 26 (가루1) · 27, 13 (가루2) |
| DRV8833 #2 | 32, 23 (가루3) · 4, 19 (가루4) |
| nFAULT (두 드라이버 묶음) | 5 (10kΩ 풀업. 부팅 때 HIGH여야 하는 핀이라 풀업과 맞음) |
| 홀 센서 1~4 (아날로그, ADC1이라 와이파이를 켜도 읽힘) | 36, 39, 34, 35 |

- **쓰지 않은 핀:** 0, 2, 12, 15 (부팅), 6~11 (메모리 칩), 1, 3 (USB), 16, 17 (WROVER 모듈이면 못 씀).
- **MCP23017:** 주소 0x20. GPA0~3 → ULN #1, GPA4~7 → #2, GPB0~3 → #3, GPB4~7 → #4. RESET은 3V3에 이어야 합니다 (보드에 이미 연결돼 있는지는 ★).
- **DRV8833 (VLT-MD012):** EEP(nSLEEP)를 **3V3에 꼭 이어야** 모터가 돕니다. 모터 전원(VM)은 5V입니다. 모터 하나에 두 핀을 쓰고 둘 다 PWM이 됩니다.
- **부품 추가:**
  - 1000µF를 DRV마다 1개, DC 잭 옆에 1개
  - 0.1µF를 가루 모터 단자마다 1개
  - I2C 풀업 4.7kΩ ×2
- **선:**
  - 단선 0.6: 1개를 사면 빨강·검정·흰색이 1m씩 옵니다. 필요량은 빨강·검정 약 4.9m, 흰색 약 3.2m이라 6개를 삽니다.
  - F-F 30cm: ESP32, MCP, ULN에 씁니다.
  - 구간별 길이는 wiring.md에 20% 여유를 넣어 적었습니다.
- **홀 센서를 바꾼 이유:** 처음 고른 A3144E 모듈(VLT-ML005)은 칩 정격이 4.5V 이상이라 3.3V에서는 규격 밖입니다. 5V로 주면 출력도 5V라 ESP32 입력을 망가뜨릴 수 있습니다. 그래서 KY-035(49E 아날로그, 3.3~5V)로 바꿨습니다.

## 5. 자동 검사 (`hardware/cad/check.py`)

```
cd hardware/cad
python check.py            # parts + rest + clash 전부 (약 10분)
python check.py parts      # 렌더 오류 · 출력판 크기 · 한 덩어리 여부 → stl/ 다시 만듦
python check.py rest       # 알약 대기 위치에서 칸 ↔ 출구 겹침
python check.py clash powder0 deckL   # 이름이 들어간 쌍만
python overhang.py         # 서포트 필요 면 (44°)
```

- **환경:**
  - OpenSCAD 2021.01 경로: `C:\Program Files\OpenSCAD\openscad.exe`
  - Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8`을 붙입니다.
- **판정 방식:**
  - clash는 `assembly.scad`의 `piece(name)` 두 개를 교집합해 부피 1mm³ 이상이면 실패입니다. 15개씩 동시에 돌립니다.
  - "한 덩어리"는 OpenSCAD 로그의 `Volumes: 2`(바깥 + 덩어리 1개)로 판정합니다. `coupon`과 `pins`는 원래 여러 조각이라 뺍니다.
- **마지막 결과 (2026-09-22):**
  - parts 22종 통과, rest 통과
  - clash 155쌍 통과 (의도한 조임 4쌍 포함)
  - overhang: "확인" 3곳은 모두 폭 2mm 이하 고리 천장이나 폭 7mm 홈 천장이라 다리(브리지)로 뽑혀 문제없습니다.
  - 알약 치마 × 바닥 교집합도 따로 확인했고, 비어 있습니다.
- **검사가 못 보는 것:**
  - 전선 자체의 부피
  - 나사 머리·너트 모형 (나사가 20개로 줄어서 해당하는 곳이 적음)
  - 가루 흐름, 알약 걸림, 홀 센서 신호 세기
  - 휨 (상판이 가루통 무게로 휘는지)
  - 프린터 공차

## 6. 출력 · 조립 순서

출력 설정은 PLA, 레이어 0.2, 벽 3줄, 채움 25%, **서포트 없음**입니다. STL은 출력 방향으로 들어 있습니다.

1. **coupon:** 결과를 `clear`, `m3_hole`, `m3_nut_af`에 넣고 `check.py`를 다시 돌립니다. `clear`가 핀, 기둥 돌기, 치마 턱의 헐거움을 모두 정합니다.
2. **가루 모듈 1벌** (auger, top, block, strap, hopper): 스크류가 부드럽게 도는지, 모터가 꽉 물리는지 봅니다.
3. **알약 모듈 1벌** (disk, skirt, floor, cover): 원판이 도는지, 캡슐이 칸에 눕는지, 자석이 읽히는지 봅니다.
4. **저울** (pedestal, tray, spacer ×2)
5. **pins**
6. **2·3번의 나머지 3벌씩**
7. **ctrl_plate**
8. **post ×14:** 눕혀서 출력합니다.
9. **큰 판 4장** (base_powder, deck_powder, base_pill, deck_pill): 가장 오래 걸립니다.

**조립할 때 주의:**
- ESP32는 점퍼를 먼저 꽂고 받침에 올립니다.
- 알약 모터는 바닥에 먼저 조인 뒤 치마 위에 얹습니다.
- 홀 센서 선은 모터 전선과 같이 상판 전선 구멍으로 내립니다.

## 9. 다음 단계: 웹 (사용자가 직접 코딩)

**합의한 방향:** 웹을 먼저 만듭니다. FastAPI + SQLite + 웹 화면으로 실제 서비스처럼 만들고, 기계는 처음엔 같은 명령 형식을 쓰는 "가상 디스펜서" 프로그램으로 대신합니다. 나중에 ESP32로 바꿉니다.

**데이터 초안:**

| 테이블 | 컬럼 |
|---|---|
| `slots` | no, supplement, kind (powder / pill), remaining |
| `presets` | no, name |
| `preset_items` | preset, slot, amount |

컵과 단위는 칸 종류로 정해지니 따로 저장하지 않습니다. 칸 종류는 하드웨어(스크류 / 원판)가 정하므로 기기가 알려 줍니다.

**첫 코드 단계:** 테이블 세 개를 만들고 예시 행을 넣는 것입니다.

**백엔드에서 깊게 다룰 거리:**
- 버튼 두 번 눌림 방지 (idempotency)
- 기기가 꺼져 있을 때 처리와 heartbeat
- 배출 상태 머신
- 재고가 모자랄 때 규칙
- 목표량과 실제 무게 기록

**보류한 아이디어:** 카페인 겹침 경고. 사용자가 보류했으니 먼저 꺼내지 않습니다.

**펌웨어 메모:**
- 가루: PWM으로 돌리면서 HX711 무게를 보고, 목표 근처에서 느리게 → 멈춤. 무게가 안 늘면 막힘으로 보고 잠깐 역회전합니다.
- 알약: 홀 센서로 원점 → 오프셋만큼 돌려 대기 위치 → 한 알마다 120°.
- 쉬는 동안에는 ULN 네 핀을 모두 LOW로 둡니다 (발열 방지).

## 11. 설계 파일 수정 규칙

- **숫자는 `config.scad`에서만 고칩니다.** ★ 주석이 있는 값은 실측 후에 바꿉니다.
- 고친 뒤에는 **반드시 `python check.py`**를 돌립니다. 10분이 걸리면 `clash 이름`으로 바뀐 부품만 먼저 봅니다.
- 부품 파일은 서로 `use <…>`로 부르고, `config.scad`·`lib.scad`·`layout.scad`만 `include`합니다.
  - ⚠ `include`한 변수와 부품 파일 안의 변수 이름이 같으면, OpenSCAD는 **파일 안의 마지막 값**으로 덮어씁니다. 경고도 없습니다.
  - 실제로 `pin_d`가 스크류 끝 핀(5)과 위치 맞춤 핀(4)에서 겹쳐 사고가 났습니다. 새 변수는 부품 접두어를 붙이세요.
- 새 부품을 만들면:
  - `check.py`의 `PARTS`에 추가합니다.
  - 조립 위치에 놓이는 것이면 `assembly.scad`의 `piece()`와 `CLASH` 쌍에도 추가합니다.
- 서포트가 없어야 합니다. 아래를 향한 면은 45° 이상이거나 짧은 다리(브리지)여야 합니다. 구멍 천장은 teardrop이나 좁은 폭으로 만듭니다.
- STL은 `check.py parts`가 `stl/`에 다시 만듭니다. 커밋 전에 한 번 돌리세요.

## 12. 디바이스마트 조회 (`tools/devicemart/`, git 제외)

사이트가 JS로 그려서 WebFetch로는 빈 껍데기만 옵니다. 그래서 스크립트를 씁니다.

- **검색:** `/goods/search` 페이지에서 `csrf_token`을 받고, `/goods/search_sse_stream?...`의 SSE 이벤트 `sphinx_result` JSON을 읽습니다.
  - `goods_status`: normal / runout / purchasing / unsold
  - `shipping_term`: 준비 기간. 1·2·3·4는 일, 6은 1주, 12는 2주, 18은 3주, 24는 4주
  - `min_purchase_ea`: 최소 구매 수량
  - `sale_price`: 부가세 별도 가격
- **상세 사양:** `/goods/view_contents?no=…`의 HTML입니다. 사양 이미지는 `smarfocus.hgodo.com/.../data/editor/goods/...`에 있습니다.
- **사용 예:**

```
cd tools/devicemart
python dm_find.py "KY-035" "M3x5 렌치볼트"     # 상위 결과: 준비 기간 · 상태 · 가격 · 번호
python dm_lead.py 15959593,1399 "KY-035" "0.1uF"   # 특정 번호의 상태 · 준비 기간
python dm_page.py 15959593                    # 상품 페이지 제목 · 품절 표시 · 사양 문구
```

- **규칙:** 사용자에게 링크나 가격을 줄 때는 **이 스크립트로 확인한 것만** 줍니다. 확인하지 않은 것은 "확인 안 함"이라고 적습니다.
